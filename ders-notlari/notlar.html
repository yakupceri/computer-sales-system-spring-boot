Computer Sales System projesi üzerinden, sorduğum sorular ve cevapları

Ders 0: Proje ve Spring Boot'a giriş

Bu proje ne yapıyor? Spring Boot nedir?

Proje bir REST API: ekranı yok, istek alıp JSON cevap veren bir sunucu programı (backend). Spring Boot, Java ile sunucu yazmayı kolaylaştıran hazır altyapı (framework). Sunucu, veritabanı bağlantısı, JSON çevirme, SQL gibi işleri o hallediyor; biz sadece "ne yapılacağını" yazıyoruz.

Dosya / klasörGörevi
pom.xmlKullanılan kütüphanelerin listesi (Maven indirir)
ComputerSalesSystemApplication.javaBaşlangıç noktası (main metodu)
application.propertiesAyarlar: veritabanı adresi, şifre vb.
domain/Entity'ler = veritabanı tabloları
repository/, service/, controller/Katmanlar (aşağıda)

Anotasyon (@ ile başlayanlar): Spring'e "bu sınıf/alan özel, onunla şunu yap" diyen etiketler.

Bir istek uygulamanın içinde nasıl ilerliyor? (Katmanlı mimari)

İstek → Controller → Service → Repository → Veritabanı
Cevap ← Controller ← Service ← Repository ← (veriler)
KatmanRestorandaGörevi
ControllerGarsonİsteği alır, cevabı götürür
ServiceAşçıAsıl iş, kurallar, hesaplama
RepositoryKilerVeriyi getirir / kaydeder

Garson (Controller) kilere (Repository) doğrudan gitmez, aşçıya (Service) gider.

JpaRepository'den türeyen repository'lerde hazır gelen metotlar: findAll(), findById(id), save(x), deleteById(id).

Dependency Injection: private final CategoryRepository repo; nesnesini biz new ile oluşturmuyoruz, Spring veriyor.

Postman ──8080──▶ Spring Boot uygulaması ──3306──▶ MySQL

  • 3306: MySQL'in portu. Oraya uygulama bağlanıyor, biz değil.

@Column(nullable = false, unique = true) ne demek?

  • unique = true: Bu değer tabloda benzersiz olmalı (TC kimlik no gibi).
  • nullable = false: Bu alan boş bırakılamaz.

JSON ve entity ilişkileri

OrderItem.order nerede, sonsuz döngü neden oluyor?

OrderItem sınıfının içindeki order alanı. Karşı tarafı Order sınıfındaki items listesi. İki sınıf birbirini gösteriyor:

Order ──items──▶ OrderItem
  ▲                  │
  └──────order───────┘

Jackson (JSON'a çeviren kütüphane) Order → items → OrderItem → order → Order → ... diye sonsuza kadar gider ve StackOverflowError verir. Çözüm: döngüyü bir taraftan kesmek (OrderItem.order alanına @JsonIgnore).

@JsonIgnore ne işe yarıyor?

Jackson'a "bu alanı JSON'a çevirirken atla" der.

Etkilenir mi?
API'nin döndürdüğü JSONEvet, alan görünmez
Gelen JSON'u okuma (@RequestBody)Evet, yok sayılır
Veritabanı kolonuHayır, değişmez
Java'da getOrder()Hayır, normal çalışır

Kullanım yerleri: döngü kırmak, şifre gibi hassas alanı gizlemek, gereksiz veriyi göstermemek. Dezavantajı: her yerde geçerli; büyük projelerde bunun yerine DTO kullanılır.

Ders 1: Uygulamayı çalıştırma, Postman, HTTP

H2 nedir, nasıl çalıştırıyoruz?

H2, uygulamanın içinde bellekte çalışan küçük bir veritabanı. Kurulum gerekmez; uygulama kapanınca veriler silinir.

  • pom.xml'de H2'nin scope'u runtime: uygulama çalışırken de kullanılabilir (test = sadece testlerde).
  • application-h2.properties bir profil: sadece "h2 profiliyle çalış" denince okunur ve ana ayarların üzerine yazar.
./mvnw spring-boot:run -Dspring-boot.run.profiles=h2

H2 konsolu: http://localhost:8080/h2-console — JDBC URL jdbc:h2:mem:computer_sales, kullanıcı sa, şifre boş.

Bu filter nereye gidiyor?

@PostMapping("/filter")              ← ADRES (URL'nin parçası)
public List<Category> filter(...)    ← sadece METODUN ADI

Tam adres: POST /api/categories/filter. Yolculuk:

  1. Controller: @RequestBody gelen JSON'u RequestDto nesnesine çevirir.
  2. Service: findByFilters metodu CategoryService dosyasında görünmez; implements IBaseFilterService sayesinde oradan "miras" gelir (default metot, 10 servis ortak kullanır).
  3. FiltersSpecification: filtreyi SQL WHERE koşuluna çevirir.
  4. Repository: SQL'i çalıştırır, sonuç JSON olarak geri döner.

GET ile POST farkı ne?

GETPOST
AmaçVeri okumakVeri göndermek (genelde yeni kayıt)
Veri nerede?AdresteGövdede (body), JSON

Filter ucu okuma yaptığı halde POST kullanıyor, çünkü karmaşık filtre listesini gövdede göndermek daha kolay. Arama uçlarında yaygın bir istisna.

Postman'de 400 hatası aldım, hata mesajı nasıl okunur?

Uzun hatada sadece 3 alana bak: status (ne tür), message (ne oldu), path (nerede). trace kısmını şimdilik okumana gerek yok.

KodAnlamıKimin hatası?
2xx (200)Başarılı—
4xx (400, 404)İstek hatalıİsteği gönderenin (Postman)
5xx (500)Sunucu hatasıKodun (Java)
  • Required request body is missing → gövde gönderilmemiş. Postman: Body → raw → JSON seç.
  • JSON parse error: Unrecognized token 'yakup' → gövde geçerli JSON değil.
  • No static resource ... (404) → o adreste bir uç yok (ya da kod derlenmemiş).

JSON nasıl yazılır?

  • Nesne süslü parantez içinde: { ... }
  • Anahtarlar ve metinler çift tırnak içinde: "name": "Laptop"
  • Sayılar tırnaksız: 1500; liste köşeli parantez: [1, 2]
  • En basit geçerli JSON: {}
{"name": "yakup"} gönderince hata gelmedi ama filtre de çalışmadı: RequestDto'da name alanı yok, Spring tanımadığı anahtarları sessizce yok sayar. "Hata almadım" her zaman "istediğim oldu" demek değil.

Olmayan bir kolonla (isim) filtre atarsam ne olur?

Cevap: 500 + "Geçersiz kolon: isim". Mesaj doğru ama kod yanlış: hata istemcinin olduğu için 400 olmalı. Bunu ileride hata yönetimi (@RestControllerAdvice) dersinde düzelteceğiz.

Ders 2: İlk uç — tüm kategorileri listele

Bir Java metodu neyden oluşur?

public  List<Category>  findAll  ()  {  return repo.findAll();  }
  ①          ②            ③      ④   ⑤           ⑥
  1. public: herkes çağırabilir
  2. Dönüş tipi: ne geri verecek
  3. Metodun adı
  4. Parantez: dışarıdan aldığı değerler (boşsa hiçbir şey almaz)
  5. Süslü parantez: gövde
  6. return ...; sonucu geri ver (noktalı virgül unutma)

Metodun adı findAll, içinde de repo.findAll() var. Karışmaz mı?

Karışmaz. repo. "repo nesnesinin findAll metodu" demek. Nokta, nesne ile metodu bağlar: service.findAll(), repo.findAll(). Nokta olmadan yazılsa metot kendi kendini çağırırdı.

Controller'da ne yazdık, adres neden /getAll değil?

@GetMapping
public List<Category> findAll() {
    return service.findAll();
}

Sınıftaki @RequestMapping("/api/categories") ile metottaki adres birleşir:

"/api/categories" + @GetMapping              = GET /api/categories
"/api/categories" + @GetMapping("/categories") = /api/categories/categories  (yanlış)

REST kuralı: adreste fiil olmaz. İşi HTTP metodu söyler.

YanlışDoğru
GET /api/categories/getAllGET /api/categories
POST /api/categories/createPOST /api/categories
DELETE /api/categories/delete/1DELETE /api/categories/1

Derleme hataları nasıl okunur?

Dosya.java:[31,12] = 31. satır, 12. karakter.

HataAnlamı / bendeki sebebi
cannot find symbol: variable repoBu isimde değişken yok (Controller'da repo değil service var)
variable service is already definedAynı değişken iki kez tanımlanmış

Kural: Her zaman ilk hatayı düzelt, tekrar derle. Arkadan gelen hataların çoğu zincirleme hatadır, kendiliğinden kaybolur.
Java büyük/küçük harfe duyarlı: @pathVariable ≠ @PathVariable. Anotasyonlar büyük harfle başlar.

Ders 3: Tek kategoriyi getirmek

@PathVariable ne işe yarıyor, neden koyduk?

Adresin içindeki değeri alıp metodun değişkenine koyar.

@GetMapping("/{id}")                         ← adreste "burada değer var, adı id"
public Long findById(@PathVariable Long id) {  ← "o değeri al, id değişkenine koy"
    return id;
}

/api/categories/5   →   id = 5

Koymasaydık Spring değeri nereden alacağını bilemezdi.

AnotasyonDeğeri nereden alır?
@RequestBodyİsteğin gövdesinden (Postman Body)
@PathVariableAdresin içinden

{id} içindeki isim ile parametre adı (id) aynı olmalı. { } olmazsa "id" sabit bir yazı sanılır.

/api/categories/abc → 400: parametre Long olduğu için Spring "abc"yi sayıya çeviremez ve hatayı isteği gönderene yükler.

Optional nedir, olmayan kategori neden 200 + null dönüyordu?

repo.findById(id) doğrudan kategori değil bir kutu (Optional<Category>) döndürür: kategori varsa dolu, yoksa boş. Kutuyu açmadan döndürünce boş kutu 200 OK + null olarak gidiyor; bu yanıltıcı, doğrusu 404 Not Found.

public Category findById(Long id) {
    return repo.findById(id)
            .orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND, "Kategori bulunamadı: " + id));
}
  • orElseThrow: kutu doluysa içindekini verir, boşsa hata fırlatır.
  • () ->: "kutu boşsa şunu çalıştır" kalıbı.
  • ResponseStatusException + HttpStatus.NOT_FOUND: Spring bu hatayı 404 olarak döndürür.
  • Service artık Category döndürdüğü için Controller'ın dönüş tipi de Category olmalı; yoksa incompatible types derleme hatası çıkar.

Araçlar

VS Code eskiden kodu otomatik tamamlıyordu, artık yapmıyor. Neden?

Java eklentisi bu projede sadece hafif modda (Lightweight / syntax server) açılmıştı. Bu modda proje sınıfları ve Spring için tamamlama çalışmaz.

  1. Sol altta Restricted Mode yazıyorsa tıkla → Trust (klasöre güven).
  2. Alt durum çubuğunda Java simgesi { } / "Lightweight Mode" görünüyorsa tıkla, ya da Cmd+Shift+P → Java: Switch to Standard Mode.
  3. Hâlâ olmuyorsa Cmd+Shift+P → Java: Clean Java Language Server Workspace → Restart.

Proje yüklenirken sağ altta "Importing Maven project" yazar; bitince tamamlama gelir. Klasörü GitHub/computer-sales-system-spring-boot olarak (proje kökünden) açmak gerekir.
